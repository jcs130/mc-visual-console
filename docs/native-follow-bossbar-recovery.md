# Native follow recovery and compact status bars

NeoForge director 0.1.35, Fabric director 0.1.25 and observer 0.1.10 address a menu/offer race: native request polling previously stopped while any screen was open. A request could expire behind a mirrored inventory, arrive after the host's receipt deadline, and strand the stopped selector on the same connection. A later subject death then left a self-camera indefinitely.

Native ingress now runs during menus and explicitly refuses new offers with `native_screen_open`; it does not execute camera actions behind a menu. `offer.neverAdmitted` is false for IDs previously admitted, even if a later duplicate is expired. Refused offers retain the prior operation's terminal reason. `terminalCameraLife` preserves positively observed death independently of an entity disappearing from current state, and clears on a new accepted request.

The public `planNativeDirectorResume` contract remains `mcvisual.native-director-resume/v1`, with an additive `reconciliation` result. Same-connection restart requires the exact stopped timeout, matching request/lease/target/connection/world, a definite non-admission receipt, unchanged prior native request/lease and either its still-attached camera or its bound death receipt and self-camera. A fresh native snapshot is mandatory; the immutable refusal itself can be historical. Manual cancellation, admitted operations, foreign cameras, stale snapshots, and unrelated terminal states remain closed. Resume archives the previous status, creates a new lease and new selection, and never replays the expired request. Supervision retains its restart budget.

An explicitly scoped observer profile can enable `compactBossBars: true` and `maxVisibleBossBars: 2` (bounded to 1–3). Only the render iteration is filtered: nonempty bars remain visible, empty/additional entries become a count and F9 details. The original UUID map, names, progress, styling, flags and native updates/removes remain intact. Equal names are not deduplicated and zero progress is not interpreted as an entity death. Original updates can make a collapsed entry visible again. `bossBarPresentation` reports original counts and up to 128 details, with explicit truncation. Unconfigured clients retain vanilla display.

Verification covers native policy/menu and immutable-death cases, standalone source and packaged-JAR consumers for both loaders, public TypeScript consumption, timeout/late-refusal/death host process replay, and manual-stop negatives. Runtime installation and real-world pixels are separate evidence. Client-side compaction does not claim that a server or mirror has correctly emitted every BossBar REMOVE; investigate lifecycle ownership by UUID before changing that side.
