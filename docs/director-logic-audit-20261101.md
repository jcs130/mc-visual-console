# 导播逻辑审计与参数化相机

2026-11-01；源码、离线验证、加载与现场效果分别记录。本文不是发布或已上线证明。

## 查到的问题

旧现役确实请求了系统一：一张真实原生帧供 action / space / continuity 三题共享编码。原调用别名为 system1，服务实测回报 StartLux-Decision-v1.1-2B-Instant；视觉编码 F16。原客户端丢掉 probabilities，只统计 keep/proposal 硬选择，模型不是完整自主导演。规则先选事件主体，也没有其他机位的真实预览。

旧代码的 keep 仅缓存五秒，过期后限流分支可能放行同一规则提案；adopted 计数只表示建议返回宿主，未证明实际拍摄。Java 虽有有限环绕/推拉，但尺寸、角度、时长基本固定，JS 参数运镜库没有接到这个原生后端。旧文档的完整仲裁器也不能当作现役事实。

## 现在的执行链

1. 宿主汇聚真实原生位置变化、成功动作、战斗和公开发言。先筛事件主体；聊天中的计划不视为已发生动作。主体选择仍以规则为主，不让单张当前镜头假装观察到远处其他玩家。
2. 原生能力和当前空间证据生成最多六个替代方案，加 keep。包含稳定跟随、平视、斜前、操作第一人称，以及仅在当前人物已验证开阔/安全楼层时提供的正交机位。有限环绕不因无聊随机启用，没有全路径证据就不进入自动菜单。
3. 一张 512×288 实景图加紧凑状态，同批询问 action / space / continuity。明确告知只有 keep 是当前实拍，其他方案没有预览。三题是同一模型的不同判断角度，不能当成三个独立模型交叉验证。
4. 每题的概率必须恰好覆盖候选 ID、数值有限且在 0..1、和在 1±0.01；只修正这个微小和误差。缺失/坏分布退回已校验硬选择，不伪造 one-hot 概率。没有两票一致就保持。
5. 概率按 1.3 / 1.2 / 1.1 加权；仅同一菜单、连接、世界及原节目请求内按新 70% / 旧 30% 平滑。先合并同人物同轨迹的参数档位，再比较机位家族。胜者质量至少 0.5、相对第二名差至少 0.12，否则保持。它们是条件分类偏好，尚未做现场概率校准，不是画面成功率。
6. 只在胜出的同人物、同 view 轨迹家族内按真实概率混合速度/高度/距离。不同主体、投影和运镜不平均。模型不能生成代码、命令、坐标或任意轨迹。
7. 唯一原生节奏门再次检查后提交稳定相机请求。收到匹配 UUID、世界、租约、请求和实际帧后才记录渲染成功；受理、模型建议、计时结束都不是完成。

## 现役原生节奏门

| 项目 | 规则 |
|---|---|
| 同人重构图 | 至少 12 秒；原生附身门至少 10 秒仍保留 |
| 换主体 | 通常至少 30 秒；确认静止超过 20 秒可在 12 秒后让位 |
| 战斗 | 当前主体八秒内有新战斗证据时保护，不因别人说话切走 |
| 切换预算 | 任何重构图/切人最多 4 次/分钟，换主体最多 2 次/分钟 |
| 返回刚离开的人 | 60 秒冷却 |
| 改变投影 | 已观察到上次改变后至少 45 秒；原生几何安全检查始终生效 |
| 死亡/已证明定位失败 | 宿主既有原生证据验证通过后可进入恢复分支，不受普通审美配额阻挡 |
| 手动/未知/取消 | 手动优先；unknown 按原请求对账，不换 ID 重试；停止后不复活 |

节奏状态按实际渲染推进。接受模型建议不会消耗或重置实际镜头时钟。宿主重启后保守重新建立现场状态；这些计数属于会话内状态，并非跨重启持久账本。

CameraChoiceArbiter 仍为有完整质量/路径证据的其他宿主提供通用评分仲裁；原生现场使用 NativeCameraPacing。后者不假造可见性、构图质量或其他机位预览来满足前者的评分门槛。两者不同时控制同一 live 相机。

## 固定脚本与参数

版本 mcvisual.camera-script/v1。SDK 的 CameraPlan.motion、broadcast_camera_take 的 MCP 输入及原生 request.motion 使用同一结构。只有能力查询显式声明后可发送；旧客户端拒绝参数方案。

```json
{"schema":"mcvisual.camera-script/v1","distance":6.5,"height":1.8,"speed":0.7}
```

上述用于跟随、前视、侧视等既有脚本。distance 2–10 格，height 相对所跟随真实眼点 -0.8–12 格，speed 0.5–1.5。运行中改尺寸采用有界渐近与每秒最大位移，机位角度来自既有脚本；不是角色飞行速度或视场角。

```json
{"schema":"mcvisual.camera-script/v1","arcDegrees":30,"durationMs":12000,"speed":0.8}
```

上述用于有限环绕；实际时长 durationMs / speed，此例 15 秒。角度 15–90 度，实际时长 4–20 秒，五次缓动峰值角速度最多 45 度/秒。有限镜头从真实当前机位开始，拒绝同时注入 distance/height 而跳到新起点；推拉用既有有终点路径。路径整体采样 65 点验碰撞，运行中继续核对，主体移出已验证锚点即阻断；到终点后需要实际帧确认 completed。duration/arc 不能偷偷套到无限跟随脚本。

原生避挡、近墙第一人称、真实 OrthoCamera 与 450ms 叠化继续保留。原生 v0.1.17 新增参数协议；仅安装依赖不代表某条路径已通过。

## 预算与证据

每题完整图文 ≤4096 token，客户端按保守字节和图像成本预检，工具描述/预留输出预算另算。默认四路传输、15 秒总超时、无重试；现役单批、至少八秒间隔、最多六批/分钟，过期帧合并/取消。分类 output_tokens=0 正常，取消会关闭 HTTP，不能据此声称服务端 GPU kernel 也已中断。
