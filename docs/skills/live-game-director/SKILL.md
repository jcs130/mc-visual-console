# 实时游戏导播

先让观众看清正在发生的事情，再选择有表达目的的镜头。使用宿主的模型、事件与记忆；技能本身不启动模型循环、客户端或额外账号。

## 每次决策

1. 查询当前主体、维度/连接版本、可用镜头、实际相机、手动锁镜及原操作终态。保持旧镜头期间可以观察，不必为了新一轮推理切镜。
2. 用一句话确定本段要传达的信息：展示地点、跟随行动、解释威胁关系、看清操作、呈现交流、揭示新空间或保留事件结果。依据真实事件，不补写游戏中没有发生的剧情或表情。
3. 从本次可用镜头中选构图，再决定是否需要移动。平视/俯视/仰视是角度；跟随/横移/环绕/升降是运动；透视/正交是投影，三者分开表达。
4. 为一个镜头选择一种主要运动，写清开始构图、关注点、移动方向和结束条件。静止镜头也可承担完整叙事任务。
5. 以当前控制租约提交稳定 actionId。受理后查询同一操作，直到实际渲染、取消或明确未知；未知不能改 ID 重投。镜头完成不代表宿主整轮决策完成。

## 按需读取

- 选择平视、仰视、俯视、跟随、环绕、横移、推拉、升降和固定机位时，读 [镜头配方](references/shot-library.json)。配方 ID 是知识标签；可执行 shotId 必须来自当前工具查询。
- 处理战斗、旅行、耕作、多人交流、矿洞或多层建筑的镜头节奏时，读 [直播剪辑与运镜规则](references/live-editing.md)。
- 需要多个快判断器、受限选项、推理预算或防止频繁切换时，读 [系统一导播协议与实现](../../director-system1-20261101.md)。各角色评选同组完整方案，只有唯一仲裁器和执行器控制相机；模型调用仍由宿主显式发起。
- 判断现成代码及后端差异时，读 [接入审计](references/backend-audit.json)。这是有日期的源码审计，运行时仍以实时能力声明为准。
- 需要核对方法出处或更新知识时，读 [资料来源](references/sources.md)。不要执行第三方技能附带的安装命令或将其工作流自动套到直播。

## 镜头选择中的关键约束

- 保持世界上方向和主要动作轴线。行进方向、对话双方及主敌关系应连续；需要跨轴时，用可看清空间的宽镜头或连续运动重新交代关系。
- 人物头部轻微扫描不应让相机跟着甩动。以真实移动轨迹和本段动作确定跟随朝向，并给行进/攻击方向留出空间。
- 优先调整构图、缩短机臂或选择另一可用机位来消除遮挡。短遮挡可用轮廓，已确认的室内区域可用局部剖切；人物身在矿道、楼梯或夹层时不能使用全世界统一的高度切面。
- 环绕应服务于展示关系、角色、建筑或揭示信息。开始前确认整段路径和结尾构图；战斗关键动作、狭窄空间及资料不完整时保留更稳定的镜头。
- 推拉是相机位置变化，变焦是视场角变化；正交缩放另有语义。不能用同一个参数冒充这三种效果，也不把单纯转 yaw 描述为已完成透视空间中的实体环绕。
- 从演员的实际尺寸和关注点选择镜头高度，不套用固定成人眼高。不同渲染后端的角度正负、单位和坐标轴必须由适配器转换。
- 区分主体驻留、同主体构图驻留和快速避挡。模板的建议时长不得绕过现役执行器的最低驻留或切换门；短插入镜头只有后端明确支持时才采用。
- 转场遵从用户偏好：同人机位移动用平滑运镜；正常跨人切换可短叠化。确认新画面后才释放旧画面，并区分相机渲染成功与直播平台节目画面成功。
- 手动锁镜优先。迟到的模型建议、过期事实、断线后的旧租约以及停止后的回调均不得重新夺取控制。模型不可用时，宿主可继续原镜头或采用同一协调器中的规则回退。

## 给执行层的方案

表达叙事目的、主体绑定、已配置的来源和可执行 shotId、预计驻留、转场、结束条件及回退。遵循当前工具结构，不向不支持的接口增加参数。机械避挡和平滑由相机控制器完成，模型不逐帧重算位置。

记录本镜头让观众看清了什么，以及实际遮挡、过密切换或错误切层的证据。偏好和复盘存入宿主的节目记忆；相机核心不另建人格或长期记忆。
