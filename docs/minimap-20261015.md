# Compact navigation map

The normal web viewer uses a small north-up map of its already received terrain. It shows the player's centered heading arrow, current coordinates and two zoom buttons. The default span is 48 blocks, with 24/96-block zoom limits. The panel is 180×224 CSS pixels at desktop width, 160 pixels wide below 900 pixels, and 128 pixels wide below 520 pixels.

The previous exploration/combat modes, perception history mask, risk clouds, entity category legend, sound directions and hover reports are removed from this inset. Agent perception, tools and memory are separate. No extra world subscription, account, server discovery or model call is introduced.

Terrain still uses the original shared scene's uploaded block buffers and section meshes, lighting, models and textures. Unknown columns and areas outside the latest sample remain hatched. The player stays centered while terrain follows true world coordinates. The inset is explicitly labelled as a surface map, including underground; its coordinates retain the body's actual height. Automatic cave clipping is removed because clipping exposed-face meshes does not create solid-rock caps and could make received terrain look empty. Actors, billboards, trails, effects and observer transparency overlays are excluded from the terrain pass; the main scene's original parent ordering is restored synchronously, including after errors.

The offscreen camera is explicitly marked. Live avatar following must not overwrite its pose, and the inset must not update the main camera's water transition. Its terrain is drawn opaque through a scoped render callback; the normal observer view's 35% obstruction transparency is restored in `finally`. This also fixes the previously masked failure where most of a loaded inset rendered as sky because the main follow callback replaced the overhead camera pose.

The inset uses a 256×256 render target instead of 384×384 and no visibility-history ray processing. That reduces readback pixel count by 55.6%; this is not an end-to-end FPS claim. Hidden panels skip sampling. Disconnects and dimension/body changes invalidate pending images; terrain older than five seconds is cleared when refreshed. Resources and listeners are released on disposal.

Validation on 2026-10-15 used the existing NarutoPi action connection on Java 1.21.1, without an extra game account or inference. The candidate showed 16/16 local map columns, original terrain, the compact controls, and no page exception or scrolling at 1040×720. Both 1.21.1 and explicit 1.20.6 browser packages were rebuilt from their matching verified original assets. Source publication, copied deployment and live acceptance are recorded separately by the consuming project; other consumers are not updated by a source push.

Regression coverage includes centered movement/heading at negative coordinates, missing-column hatching, pending readback after a dimension change, hidden/disconnected state, expired GPU results, disposal, live-follow isolation, water-state isolation, opaque-map/transparent-main restoration, and original scene ownership/order after failure. The final shared test logs disclose conditional external native-asset skips; these are not full native gameplay or pixel-parity acceptance.
