# Observed projectiles and shield use

The Mineflayer stream previously bypassed its 100 ms entity batch only for arrows and tridents. A potion spawning and disappearing inside that window could therefore be absent from the browser entirely. All actual `projectile` entities and the eye of ender now use the bounded immediate path, retaining the same distance, entity-count and transport-backpressure limits. Removal remains authoritative; no projectile lifetime is extended for visibility.

The browser no longer relies on a nonexistent `splash_potion` entity renderer. It keeps the actual Java `potion` identity and reads its received item stack. Original item models, textures, extrusion and potion colors distinguish splash/lingering bottles and effects, including explicit custom black and empty stacks. The independent observed layer also handles eggs, pearls, experience bottles, snowballs, fireballs, dragon fireballs, fireworks, tridents, llama spit, shulker bullets, wind charges and wither skulls. Existing original arrow rendering remains in place. The Java 1.21.1 registry's 17 projectile types have explicit paths.

Original color/registry and selected baked model-layer data are reproducibly exported by `tools/export-observed-projectile-data.mjs`; the exporter verifies its two original inputs by SHA-256. Numeric item IDs come from the connection's registry. Potion/effect numeric registry colors are verified for 1.21.1; unknown version-specific colors are explicitly unavailable, while explicit custom colors and named ordinary projectiles remain usable. Special render-pass animation, glint and Java pixel parity are not claimed. No replacement cubes or fabricated projectile physics are introduced.

Shield possession is distinct from use. Own-body packets and remote living-entity use flags preserve the actual active hand. Release, item changes, death, sleep and identity/epoch changes revoke inappropriate use. Both first-person hands and vanilla avatars receive original shield geometry and UVs. YSM uses a model's dedicated shield-use clip when present; a standard articulated rig without that clip gets an explicitly identified viewer presentation pose, aligned through its original item locator. This does not modify model files or report a successful server block. Unsupported rigs stay explicit. Procedurally movable bones remain separate when batching meshes.

Validation includes full shared tests/types, original-asset model tests, short-lived entity streams on Java 1.21.1 and 1.20.6, async loading/removal/reused-ID tests, original shield geometry and both-handed defense/release tests. A private, offline WebGL gallery and a full-page socket replay verified potion visibility/removal and hand-use transitions without a game account or gameplay commands. Offline samples are not natural live combat acceptance. Private character assets and captures are excluded from this repository.

Consumers must freeze and pin the matching browser bundle and backend stream. A browser-only static update can improve rendering of already delivered events, but cannot repair events still dropped by an older backend.
