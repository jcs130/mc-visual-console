# 游戏消息分类与回看

适用于现有 1.20.6 Web 视图和 OBS 覆盖。共享代码改动不代表消费它的远端网页已经更新。

左下角「消息记录」可展开最近消息，切换聊天、私聊、任务提醒、系统与详细回执；支持搜索、未读数、清空和收起。只读操作不会发聊天、执行 CLI 或操作物品。

消息先进入历史，再应用屏幕短提示的限流。长提示、链接和被公会看板消费的文本仍可回看；私聊单独着色，保持来源类别，不能靠消息内容冒充服务器任务。

`MC_*` 系统回执归到「详细回执」并默认折叠，避免 JSON 刷满画面。仍保留原 Agent 连接和机器回执；不修改服务器发送内容或 Mineflayer 解码器。聊天里玩家自己写的 `MC_*` 只是普通聊天。

## 数据与生命周期

- 使用既有 `gameMessage { kind, text }`，不增加宿主必需字段或端口。
- 本页内存最多200条，每条最多4096字符；技术回执最多40条，不挤走全部普通消息。动作栏不进入历史，避免每帧提示刷屏。
- 不写浏览器本地存储、不跨账号共享。服务器确认的 `viewerSession` 身份/世界改变、脱离附身或断线会清理历史及旧短提示；同一对象重复快照不清空。
- 脱离的观战会话不显示迟到消息。新会话只显示新收到的数据，不重放上一个人的私聊。
- `photo=1` 不创建面板；OBS 保持主画面透明，消息入口仍可使用，不自动展开历史。

宿主仍应只转发当前动作玩家或服务器确认的实际附身对象已收到的消息，按已有协议正确设置 chat/system/whisper。前端不能从匿名 system 文本推断真实私聊双方。

## 更新与验证

按原 Minecraft 版本和 preset 重建资产，核验 `viewer-client.json` 的源码/浏览器bundle摘要，再重启消费该目录的 Web 宿主。只拉源码或刷新页面不能替换旧bundle。
