# Web 人物模型选择

在画面右上方打开 **人物模型**，选择当前观战人物的模型和配色。默认 **跟随服务器**；点击 **恢复服务器外观** 会使用服务器最近一次同步的外观。

选择只影响 Web 观战。它不修改服务器角色、其他玩家看到的外观、游戏状态或 Agent 行为；不发送游戏命令。原生页面按素材清单 URL 与玩家 UUID 保存明确选择，刷新、断线及同一账号重生后恢复该账号的选择；存储被禁用时在当前页面内保留。不同账号独立选择。Paper 页面配置原模型目录后，按配置的作用域与玩家 UUID 保留选择；未配置时仍使用临时选择。服务器外观在本页替换期间继续更新。

## 可选资源

- Paper / Socket.IO 页面：已收到并通过宿主校验的公开 YSM 原始模型与贴图，另有明确标注的「原版玩家皮肤（Web）」选项。资源缓存过期会显示原因并恢复服务器外观。
- Paper 页面还可按配置提供本地原始 YSM 2.4.1 模型。逐文件 SHA 与长度验证后列为「Web 原模型」；指定账号的默认值只应用于本人实际 `avatarState` UUID，不要求服务器先分配该模型。服务器仍未同步时，原始服务端观察保持不可用，Web 外观不会伪造 Freesia 状态或修改其他玩家看到的角色。
- 原生 1.21.1 页面：部署素材清单中已锁定的 YSM 2.6.5 原始 Alex / gsl、Steve / tartaric_acid、Default Boy / blue、Default Boy / red。只有版本、来源与逐文件 SHA 匹配的模型才出现在列表中；加载时继续校验实际字节。
- 自带原始模型目录：宿主提供通过逐文件 SHA 校验的 catalog 后，可选择其 YUI / `neko_yui` 2.4.1。其客户端外观适配读取本人普通 Mineflayer 的 pose、50ms physics、velocity、inWater、health 和 handAnimation，复用已有 YSM 动画层；不伪造官方 Mod motion。朝向缺少独立 bodyYaw 时明确使用本人 look yaw。跑步、攀爬、骑乘、飞行及额外动作只有实际字段存在时选择；健康下降驱动受伤动作并标注来源。原图、骨骼及 UV 保留，逐骨骼合批降低网格数量，不宣称 FPS 或 Java 像素一致性。

`bootNativeConsole`、`mountNativeWorld` 和 `NativeSelfPlayerController` 接受 `defaultAppearance`、`selectionStorage`、`selectionScope`。默认外观仍为 `server`；薄宿主可提供 `bundled:yui-ysm` 默认值，已保存的明确选择（包括 `server`）优先。存储只包含选择 ID，不含动作、账号名称或凭据。模型资源按 actor 生命周期释放，偏好按账号隔离。

原生宿主 `prepareNativeWorldPreviewHost` 的 `defaultAppearance` 经校验后写入页面的本地外观属性，实际浏览器启动读取它；根路径与嵌套 `basePath` 使用相同接线。默认仍为 `server`，属性仅包含外观 ID，不包含宿主配置、账号或凭据。无效 ID 拒绝生成页面；资源不在清单内时沿用选择器的服务器外观回退。

宿主可另传 `selectionScope`（24–64 位小写十六进制不透明摘要）隔离服务器/账号；未传时沿用清单 URL 作用域。Neko 采用已有 Settings.identity，不改变身份计算或游戏状态。旧清单 URL 偏好没有服务器来源，保留原条目且不自动搬入新作用域；升级后请在人物模型中重新选择一次（包括「跟随服务器」）。新作用域内的明确选择随后优先于宿主默认，并在相同身份重连、重生、刷新后恢复。

没有恢复旧 VRM 下拉菜单：旧构建关闭它时，相应资源并未随部署包提供。本功能复用现有 YSM 渲染器，不增加任意文件上传、下载或私有 `.ysm` 解密入口。人物朝向、运动、隐身及身份绑定仍来自同一玩家；不适配的动画、装备和第一人称能力仍沿用现有提示，完整 Java 渲染一致性不因外观选择而变为已验收。

## 接入边界

共享选择器 `appearance-settings.js` 只通知本地显示适配器。Paper 的 `PaperYsmPlayers` 在原始服务器状态之上保存单独的临时选择；原生的 `NativeSelfPlayerController` 使用 `webAppearance`，明确记录 `web_viewer_override`，不伪造服务器 YSM attachment。

快速连续选择、实体 ID 复用、断线或销毁后，旧的异步加载结果会被释放。恢复操作使用当前服务器状态；服务器不支持的外观保持明确不可用，用户仍可主动选择列表中可用的 Web 模型。

## 构建与验证

### 当前浏览器上传 PNG 皮肤

Mineflayer / Paper 的网页「人物模型」面板提供 PNG 上传和宽臂 / 细臂选择。支持 64×64、64×32 及同布局的高清图片，最大宽度 1024、文件 4 MB。图片在本地校验、解码，原 PNG 及其 SHA 保留；标准旧版布局按 `skinview-utils` 转换到玩家模型的完整 UV 布局。原始文件不改写，宽臂与细臂使用不同的外观版本。

皮肤只保存在当前浏览器，按页面作用域与实际玩家 UUID 隔离；不向 Cortico 或 Minecraft 发送上传请求、命令或外观变更。刷新、重连或重生后恢复同账号的选择。浏览器禁用存储或空间不足时，明确提示只在当前页面保留。「恢复服务器外观」继续优先于部署默认值，原 YSM 也仍可从列表选回。本人尚未确认时禁用上传；读取图片期间断线或换账号，旧请求不得把皮肤套到新角色。

上传 PNG 使用标准 Minecraft 玩家模型和本人运动输入。它是明确的 Web 外观选择，不能冒充服务器 YSM 绑定或完整原生动作 / 装备渲染。原生 Java 数据页面的现有模型选择保持原契约，本次上传入口针对当前 Mineflayer 页面。

### Paper 本地原模型配置

使用既有 `mc-bundled-appearances/v1` 原始资源清单（`host/native-bundled-appearances.mjs`），在新目录生成静态资源：

```sh
node tools/install-paper-appearances.mjs <catalog.json> <new-player-appearances-directory> --player-uuid=<actual-own-uuid> --default=bundled:<catalog-id> --scope=<24-64-hex-identity-scope>
```

将生成目录按部署配置放在网页资产的 `public/player-appearances/`，并重新构建该版本的浏览器包。原始文件保持字节不变，角色资料和具体 UUID 留在消费端，不内置共享源码。配置是可选的；404 不影响现有页面。缺文件、哈希不匹配或版本不匹配明确显示失败。嵌套页面按当前 `index.js` URL 读取同一作用域目录，不扫描服务器或本机目录。

「恢复服务器外观」这一明确选择优先于部署默认值；刷新及重连后继续保持。断线释放旧模型和实体，重生后等待同账号的实际新身体事件，再重建模型。资源加载与几何测试不代表已经恢复 Minecraft 连接，也不代表完整 Java 像素或动画一致性。
