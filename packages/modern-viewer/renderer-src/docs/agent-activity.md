# Read-only thinking and tool timeline

The modern Mineflayer viewer accepts the optional trusted `viewer:activity` bot event. Browser drawing uploads cannot supply this event. A host supplies records with `id`, ISO `at`, `kind` (`reasoning`, `message`, `tool`, `execution`, `decision`, `phase`), `source` (`system1`, `system2`, `human`, `unknown`), `status` and `title`. Optional `text`, `arguments`, `result`, `model`, `run`, `session`, `round`, `callId`, `taskId`, `durationMs` preserve actual provenance. The core's `publishAgentActivity` port can forward these records across its engine process.

`reasoning` displays only text actually returned by a model. An absent or encrypted reasoning body is unavailable; the viewer never invents it or reads a system prompt. A completed model function-call item starts a tool row; tool acceptance and asynchronous Minecraft terminal receipts remain separate. Source attribution must be supplied by the host; unknown stays unknown. System one is orange and system two blue, matching the existing action markers.

The panel starts collapsed, supports independently expandable records, uses text nodes for all payloads, preserves open rows across updates and participates in viewer/OBS visibility preferences. The bounded history retains at most 80 records and approximately 256 KiB. Initial subscribers receive a snapshot; later frames contain only changed identities. No history is sent in the 10 Hz geometry frame. Authentication commands, structured credential fields and common credential forms are redacted before presentation. Raw system/user prompts, images and encrypted reasoning are excluded.

This surface does not call a model, dispatch a tool, open inventory, or establish that a result goal succeeded. The host adapter is optional. Without a source the panel explicitly waits for records. Native Java hosts must implement the same explicit source before reporting this surface available; a rendered model is not evidence that an activity feed exists.
